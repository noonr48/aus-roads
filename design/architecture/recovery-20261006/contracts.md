# Recovery seam contracts

## Local explicit visit/preferences mutation
Surface: ExplorationStore setters + ExploreViewModel mutation/retry pipeline. Inputs: existing explicit result/category/visited flag or confirmed clear; output: observed persisted preferences and truthful UI completion. Preconditions: successful preferences read, except existing explicit confirmed malformed-history recovery. Postcondition: latest successful history intent survives Retry and unrelated failed preferences remain. Errors: cancellation propagates; storage failure is retained/sanitized; visit capacity is separately actionable and not endlessly retried. Idempotency: setting the same value is safe; confirmed clear supersedes older history intents, not future ones. Versioning: no persisted shape/identity change; additive transient visitLimitReached=false for presentation.

## Essentials recovery
Surface: existing loadEmergency/selectCategory actions used by NearbyScreen Retry; public signatures retained if possible. Input: selected category/current area. Output: bounded initializer retry and refreshed query state. Preconditions: actual Retry requested; no fake READY. Postcondition: catalog is revalidated/opened through SearchInitializer off Main and same selected category is refreshed through normal generation/readiness observers. Errors: bootstrap failure stays visible with fixed health witness; canceled/superseded attempts do not publish. Idempotency: repeated Retry while one retry is active is coalesced. Versioning: constructor addition, if needed, must preserve existing test callers through a safe default or coordinated test edits; UI action seam uses existing methods to avoid dual recovery implementations.

## Catalog activation and public producer
Surface: FtsSearchRepository.open + SearchInitializer.initialize + bundle-search-catalog.py. Inputs: contained active pack or validated public bundled component. Output: READY/generation or failure/fallback, consistent database/metadata pair. Preconditions: integrity/schema/hash/domain validation and supported kind/tag/coordinate types. Postconditions: no invalid result publishes READY; same-query readers reject superseded generations; startup/replacement events are observed. Errors: malformed SQLite/row/hash/path and producer I/O faults are visible without payload leakage; old published pair remains on ordinary exception. Idempotency: repeating a valid open/rebuild is safe and serial; duplicate boot events may be coalesced but not lost. Versioning: retain existing metadata schema and optional legacy tables. Multi-file crash atomicity is not certified by exception rollback.

## Native map hit/render crossing
Surface: MapScreen native hit consumer and MapAssetJourneyInstrumentedTest. Input: canonical first feature/current pin ID; output: matching editor or no pin editor. Preconditions: actual same native view, applied Compose update, valid viewport/focus/camera and current style. Postconditions: a deleted/stale feature cannot edit an unrelated pin; meaningful base geometry can prove render without labels; native deletion eventually acknowledges canonical zero with physical negative control. Errors: real asset/style/native failures remain bounded/visible and recorded; no timeout inflation or SDK/renderer substitution. Idempotency: repeated missing hit has no mutation. Versioning: preserve IDs/lifecycle/service ownership. Traffic severity is a scalar match input with LOW/MEDIUM/HIGH scalar labels and explicit fallback, validated against actual SDK layer state.

## Room preservation
Surface: AppModule pin provider and RoutesModule route provider. Inputs: existing private databases and supported versions. Output: fresh/current/supported-migrated database, or explicit migration failure. Preconditions: same filenames/package, existing migrations. Postconditions: all known rows preserved; unknown versions are not deleted. Errors: Room version/schema mismatch fails closed and remains diagnosable; no silent reset. Idempotency: repeated supported open is safe; failed unsupported open preserves bytes/rows. Versioning: no new database version; retain both supported legacy pin shapes.

## GPS registration, retry and Stop
Surface: real network fused adapter -> NavigationLocationSource Flow -> NavigationViewModel. Inputs: existing request interval/permission/session; output: real fixes or failure/visible no-fix state. Preconditions: offline never links location implementation; fine-permission gate retained. Postconditions: Task failure/cancellation ends the flow, bounded retries run, cold no-fix becomes visible, cleanup removes actual callback and Stop forbids late resubscription/publication. Errors: registration and exhaustion receive fixed privacy-safe seam witnesses with attempt identity; cancellation is control flow, not a fake healthy fix. Idempotency: Stop and cleanup may repeat safely. Versioning: retain source interface when possible; no simulated position or permission changes.

## Optional adopted routing authority
Surface: InstalledPackPaths optional routing selector -> existing boot/full-record observer -> RoutingInitializer -> concrete ValhallaRoutingEngine. Inputs: same bounded current.json/version/nullable routingPath; output: configured contained component or explicitly unavailable future routing. Missing/null optional routing is supported, not a failure; corrupt/oversized metadata, non-string/blank declared paths, escape/symlink/missing/empty files are rejected. No conventional/orphan/previous fallback or fabricated routing default. Ready state is cleared on absent/rejected/failed replacement and published only after coherent configuration construction. One engine boundary serializes existing valhalla.json writing and native per-request reading; check readiness within that boundary, off Main. Current NavigationState/VM/service/notification ownership is untouched. Fixed persistent routing-init witness distinguishes failure/recovery without paths/version/exception payloads. Constructor/configuration success does not establish usable graph or a successful route; a real existing valid-tar journey is separate evidence. No new graph, schema, filename, identity, dependency-version or Android actor-close machinery.

## Referenced pack Retry preservation
Surface: actual MapPackDownloadWorker extraction/cleanup -> PackInstaller finalization -> existing PackStateStore/EvictionManager. Inputs: retained attempt version and optional supplied manifest. Postcondition: stale Retry cannot extract over or delete bytes referenced by current.json or previous.json, including late failure cleanup; normal new-version install, cancellation/resume and supported manifest-less legacy behavior remain. Supplied malformed manifest must fail visibly, not become null and silently skip verification. Preserve current/previous metadata and tar/tile/search sentinels; no storage-layout or format redesign. This addresses source-confirmed stale-Retry overwrite risk, not an inferred crash attribution. Any unprotected adoption/extraction race revealed by the actual boundary test must be repaired before general replacement-safety claims.

## Verification and wireless upgrade
Surface: original run_native.py and trusted phone --no-recovery install. Inputs: final source/APK/test SHA, exact disposable guest; final same-signer arm64 Pixel artifact. Output: explicit named-case terminals, actual images/actions, literal install Success and installed readback. Errors: missing/ignored/crashed/stale cases are failure, not pass; uncertain install is inspected rather than retried blindly; locked UI is a separate ordinary-unlock gate. Idempotency: evidence runs use controlled/restored fixtures; preserving in-place install never substitutes for data/UI acceptance. Versioning: retain application ID/version upgrade/signing identity; no uninstall, clear, grants or credential changes.
